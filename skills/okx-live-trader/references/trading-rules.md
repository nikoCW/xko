# 交易与提醒规则 v2

这些数值是可审查的保守默认值，不代表已验证的盈利策略。执行计算在 `rules.py`，以部署的 `get_rules` 为准。

## 账户总规则

| 项目 | 规则 |
|---|---|
| 单笔风险 | 结构止损损失 + 估算开平手续费和滑点 ≤ 净值0.5% |
| 名义本金 | 单标的 ≤ 净值20%；杠杆不能放大此上限 |
| 现金 | 新交易后保留净值30%的可用USDT；不把冻结余额当现金 |
| 合约 | 仅USDT线性逐仓，开仓1–3倍，net单向持仓；禁止全仓、币本位、期权、借币 |
| 总风险 | 合约止损风险政策上限3%；本版不允许已有合约、挂单、机器人风险时继续新增 |
| 暂停 | 观测当日净值高水位回撤≥3%、未知订单、保护缺失、人工暂停均禁止新增风险 |
| 重复交易 | 同标的开仓冷却15分钟；一个预览只提交一次 |
| 费用 | 使用账户taker费率绝对值与0.1%保守下限较大者；每边另估0.1%滑点 |
| 回撤计量 | UTC自然日，本服务观测到的净值高水位；非交易所完整已实现日损益。出入金可能触发保守暂停 |

首版会阻止存在同币现货库存时加仓。不做摊平、马丁格尔、翻倍、自动充值保证金或自动修改杠杆。减仓不需要新的入场信号，也不受现金储备和日回撤规则阻碍。若原订单状态不明，先核实；必要时直接在OKX处理风险。

## 买入 / 开多

1. 标的 live，上市≥7天，对应USDT现货日成交额≥500万，报价年龄≤15秒，价差≤20bps。
2. 以**之前20根已收盘15m高点**为突破位；之后一根15m收盘突破，再之后独立15m回踩并收盘守住。只支持紧接着的一次回踩，不把同一根K线当成两次确认。
3. 突破K成交量≥前20根均量1.5倍；最近收盘4H收盘价高于20根均值。最近收盘1H涨幅>4%则禁止追多。
4. 止损不得比结构失效位更靠近入场；参考回踩低点/突破位外0.2%缓冲，输入必须满足 tickSz。目标由真实阻力和结构选择，不能为凑盈亏比任意编造。
5. 扣除成本后的目标收益/止损损失≥2。预览只有在账户、数量、现金、风险都合格时生成。

## 开空

现货禁止开空。USDT线性合约使用对称规则：突破前20根15m低点、下一根反抽不过、放量、4H趋势向下；最近收盘1H跌幅>4%不追空。止损在结构高点外，目标低于入场。

永续资金费率绝对值>0.1%暂停开仓；交割合约距到期不足7天暂停。止损距离必须小于 `0.5 / 杠杆` 的入场比例，作为保证金缓冲，但这**不是交易所强平价模型**；实际强平仍受维持保证金、费用和行情影响。

## 卖出 / 平仓

- 现货卖出数量不得超过可用基础币库存；存在同标的策略卖单时先核对冲突，撤单需单独预览。
- 合约平多为 sell，平空为 buy，`tdMode=isolated`、`posSide=net`、`reduceOnly=true`；数量不得超过当前相应净持仓。
- 入场保护绑定一个止损和一个目标，全量退出，不在1R自动分批止盈，以免名义2R变成不足2R的加权收益。
- 手动止盈、减仓、移动止损、撤销保护均需新的具体预览。本版本没有修改订单/移动止损接口；不要声称已修改。
- 现有自动止盈止损由交易所执行，不依赖本服务在线。服务监控是辅助核对，不能替代交易所保护。

## 网格

### 现货网格：当前可规划与提醒

- 无杠杆，仅4H震荡区间；最近20根4H的首尾位移≤区间宽度35%，边界在该窗口真实高低范围之内。
- `止损 < 下界 < 当前价 < 上界`，3–50格，价格和数量按tick/lot向下量化，单格不得低于最小量。
- 总预算≤净值10%；按“全部预算在上界买入、跌至止损”估算库存最坏损失，加上费用滑点≤净值1%。这不含极端跳空的额外损失。
- 单格毛收益必须大于双边费用、滑点及0.1%余量；若网格过密则拒绝规划。
- 正确运行规则是买入成交后，按**实得库存**在上邻格卖出；禁止裸卖、无限补单、扩宽区间、追加预算、翻倍补仓。首次上方卖单也需要已有库存。
- 下破止损：停止新增、核对库存和订单、生成退出预览；上破上界：停止补单、重新评估，不自动追涨重建。
- 本服务没有交易所网格启动、补单和停止接口。当前不会按网格规划自动挂单；只能给规划及相关价格提醒。不要将网格规划价格直接循环提交到突破策略入口。

### 合约网格：暂不开放执行

若后续实现，必须单独覆盖：总预算及所有格子同时成交的保证金、净多/净空库存上限、资金费率、预估强平缓冲、逐仓保护、停机时先撤单再处理剩余仓位、部分成交与重启恢复。当前不能借用现货网格参数声称已经通过这些检查。

## 执行状态与故障

1. 预览有效期120秒，保存精确订单和账户指纹；确认参数一旦变化必须重新预览。
2. 重新获取余额/持仓/挂单、规格、费用、报价及入场信号；报价漂移>0.5%、账户结构变化或风控允许数量下降则失效。
3. SQLite事务领取一次执行权；固定client ID，数量不自动增大。FOK限制最大成交价并避免长时间挂单/常规部分成交；不支持无界市价或长期入场挂单。
4. 检查OKX顶层code和逐项sCode。明确参数/余额/最小量拒绝记为rejected；其他不明响应、超时、网络断开只核对原ID，不重发。
5. 交易所订单状态 filled 后再核对附带止盈止损的真实策略ID、方向、数量、价格和状态。没有证据时记 protection_pending、暂停开仓并提醒。
6. 如果交易所尚查不到订单，保留 unknown。不要删数据库、换client ID或通过重新部署“解锁”；先在OKX核实订单和仓位。若无法自动证明结果，需要人工核对日志及交易所记录后维护状态。
7. 取消现有普通/策略单同样先预览确认；取消保护后新增风险保持暂停，人工核对后才能恢复。

## 提醒

- 上穿/下穿价格，首次观测已满足时也提醒；持续处于阈值一侧不重复轰炸，回到另一侧后可重新触发，仍受冷却限制。
- 默认15分钟冷却；最多20条启用提醒。常驻监控默认每60秒一轮，接口耗时会延长间隔，不能当作低延迟止损。
- 订单未知、保护缺失、成交/撤单状态变化写入事件记录；已知未完成订单后台按原ID核对。
- 后台读取账户，现金比例低于30%、日内回撤达3%、合约缺少可核实全量保护、标记价距返回强平价不足5%时写入风险事件；后三者暂停新开仓，不自动平仓。缺失强平价时不能推断强平安全。
- 无webhook时事件仅在本地，用户通过get_events读取。配置webhook后为至少一次投递，接收端按事件ID去重。后台不会自动发单或撤单。
- 服务离线时不工作；重启会恢复提醒配置，但无法重放离线期间的每一次价格穿越。
